# GEO/SEO 打法剧本（面向 AI 引擎的可见度工程）

目标：让品牌进入 AI 引擎（豆包/DeepSeek/Kimi/元宝/秘塔/文心等）的总结性回答与推荐名单——被**点名推荐**，而非传统搜索排名。

## 1. 关键词调研（五步法第 1 步：research keywords and competing pages）

1. **多路采样（社区真实讨论优先）**：品牌词 / 品类词 / 场景词 / 竞品痛点词（「XX 缺点、替代品、数据导出」）/ 蓝海技术词，各跑多路检索。重点抓**用户原话提问句式**（知乎/社区/晒帖），不是关键词工具的抽象词。
   - **工具**：`last30days <词/竞品>` 取近 30 天跨平台真实讨论与互动量（Reddit / X / HN / GitHub 等，按热度排序），比搜索引擎采样更接近「真人此刻在说什么」；无该 skill 时降级为多路 WebSearch。
     **注意其语言边界**：免 key 版本只索引英文为主的平台，**中文产品/中文话题实测返回全空**——中文关键词调研走多路 WebSearch + 中文社媒间接采样，`last30days` 仅用于英文赛道与海外趋势（需中文社媒覆盖时，得另配 X / ScrapeCreators / 小红书 key）。
2. **AI 工具侧数据**（GEO 特有）：对话界面多需登录，用三路间接通道——①公开的引擎引用行为研究（各引擎爱引什么源）；②网上晒出的「我问了 XX」真实推荐结果；③痛点词的社区原生提问。
3. **产出关键词语义地图**：主题域（A/B/C…）→ 词组 → 长尾疑问三层；每条标注意图/竞争度/竞品占位/我方现状/优先级。搜索量暂为定性判断时标 `[未验证]`。
4. **竞品占位分析**：谁排在答案位（官方域内容矩阵？横评文？排行榜站？），记录为 competitor-intel。
5. **判定打法**：品类大词被垄断 → 侧翼（趋势词/痛点词/长尾问答/技术蓝海）；蓝海确认标准=现有答案全是旧方案、无同类 SaaS。

## 2. AI 引擎信源图谱

逐引擎记录信源偏好（基于公开研究+实测修正），决定内容投到哪：

- 典型格局示例（须按最新研究复核）：某引擎吃字节系内容与小红书；某引擎重新闻媒体与知乎；某引擎 ~70% UGC、偏爱 PDF 报告；某引擎公众号占比 ~50%。
- 机制级发现单独记录（如信源信用分、多源一致性门槛）——它们直接决定内容策略与口径治理优先级。

## 3. 可见度诊断（月度机制）

1. **探针实测**：用固定问题集（品牌/品类/场景/痛点词）逐引擎提问，记录是否提及我方、推荐了谁、引用了什么源。
   - 匿名可用的 AI 搜索（如秘塔类）→ 自动化探针，同题每月重跑出趋势。
   - 需登录的引擎 → 两条路：自动化浏览器打开登录页由用户扫码，之后 AI 接管全部提问/记录/截图；或用户 App 内手动提问截图回传。验证码对抗不值得投入，直接走登录路线。
2. **基线指标**：固定问题集的我方提及数（如 V=0/3）。产出 `results-and-learnings/<年-月>-诊断.md`。
3. **技术面检查**：robots.txt（含 AI 爬虫白名单）、llms.txt 与页面 .md 直取、sitemap 覆盖度、跳转方式（301 优于 meta-refresh）、备案等站点信任指标。

## 4. 补位内容与最短路径

- 诊断找「答案位有真实提问、但我方缺席」的缺口 → 按内容生产管线（见 workflow-content-production.md）补位。
- 三类经典最短路径：平台发对比横评文（进推荐池）、答题平台回答竞品替代品类问题、官网 blog 打开发者工具垄断的空白位。
- 内容让 AI 可引用：干净的对比表、明确的人群结论、术语与用户提问句式一致、多源口径一致。

### 答题平台：怎么找到真正该回答的问题

**最大的坑**：拿竞品情报术语当搜索词（如「XX 替代品」「数据导出」「收藏吃灰」）——**这些是内部语言，不是用户口语，搜出来的结果会是零**。用户只会描述场景（「存进去的东西还能拿出来吗」），不会用行业黑话。

按效率排序的三条路径：

1. **平台官方问题池**（效率最高）：知乎「创作中心 → 等你来答 / 推荐问题」——官方按领域推荐的高流量待答问题，比在搜索框里翻高一个量级。
2. **真人句式搜索**：把每个选题的「真实用户会怎么问」列成清单逐条搜，看下拉联想词、结果的「问题」分区、「相关问题」推荐。
3. **自己提问**（兜底）：搜不到不等于选题无效——**没人在问说明答案位空着**。且问题页本身会被搜索引擎与 AI 引擎收录，「提问 + 结构化回答」就是天然的 FAQ 对，正是引擎最爱的摘录格式。提问文案要口语化、带具体场景、不带品牌营销味。

**题目筛选四标准**：关注/浏览有基础量 → 回答数适中（10–100，太多新答沉底、太少没流量）→ 问题长期有效（避开时效题）→ 问法与内容意图匹配。

**自问自答的风控**：优先用不同账号提问（同账号自问自答推荐权重会被压低）；提问后隔 1–2 天再答；提问文案不要写成评测标题。

**答完再回填**：拿到问题链接后，按问题措辞微调回答首句（让开头直接命中提问）——对平台排序与 AI 引用命中率都有帮助。

## 5. KPI 与行动方案

- 方案按 NOW（1–2 周）/ NEAR（3–6 周）/ FAR（7–12 周）分阶段；每项标注攻击的答案位与优先级。
- 指标基线化：探针提及数、关键问题被引用数、口径一致性、收录情况——各设 4 周/12 周目标。
- 无动静时的排查顺序：内容是否被收录（site 检索）→ 是否进候选池 → 补「万能通」平台分发而非单平台加码。

## 6. 节奏

- 每月：探针重跑 + 诊断报告 + 与上月对比。
- 每季度：信源图谱复核（引擎规则变化快）。
- 每年：关键词地图全量刷新。

## 7. 中文平台的检索与验证约束（实测沉淀）

中文内容平台的**站内检索**与**链接验证**都会撞到登录态与验证码，硬闯是纯浪费——踩过的坑与正确姿势：

| 场景 | 硬约束（实测） | 正确姿势 |
|---|---|---|
| 找答题平台的目标问题 | 知乎搜索页未登录返回「安全验证·请您登录后查看更多专业优质内容」 | **不要硬闯**。给用户「搜索关键词 + 选题筛选标准」，由用户在登录态下选定问题；拿到问题链接后按问题措辞微调回答首句（对排序与 AI 引用命中率都有用） |
| 搜索引擎找站内页面 | 搜索引擎对站内问答页收录零散；百度常触发图形验证码；Bing/DDG 的 `site:` 查询常返回空或噪声 | 关键词调研走 WebSearch 泛检索拿「讨论热度与用户原话」，**具体问题链接交用户侧** |
| 验证平台文章是否真的上线 | 头条 PC 端对所有文章都返回 200 + 反爬 JS 空壳（**无判别力**）；移动端 `m.toutiao.com/i{id}/` 才有判别力 | **必做对照组**：同会话（或同命令）测 1–2 篇已知可打开的同平台文章，再测目标链接。差异才是证据 |
| 确认页面渲染结果 | 静态抓取常拿不到正文 | 真实浏览器渲染 + `title` / `body.innerText` 取值，比 HTTP 状态码可信得多 |

**验证纪律（重要）**：判定「链接失效」必须同时满足 ① 目标链接异常 ② 同平台已知可用链接正常。只有 ① 没有 ② 的结论一律视为**方法问题而非内容问题**，不要拿它去质疑用户。

**链接失效的排查顺序**：先怀疑复制有误（ID 位数/串行）→ 再怀疑非公开状态（审核中 / 仅自己可见，外部一律 404 但作者登录可见）→ 最后才是下架。给出排查清单（App 内分享重新复制、创作后台看状态、截图回传）比反复重试有效。

**顺带留意的信号**：平台页脚/IP 属地显示异常（如城市与发布地不符）可能意味着代理出口，海外 IP 发布国内平台**存在风控限流风险**——可提示用户注意，但不可当作结论陈述（标 `[推测，未验证]`）。

## 8. FAQ 页：长尾问答的批量占位

FAQ 是**单位成本最低的 GEO 资产**——一条问答就是一个答案位，且「问句 + 结论先行短答案」正是 AI 引擎最愿意整段摘录的结构。长文抢的是主题，FAQ 抢的是长尾提问。

**什么时候做**：自有站/平台需要一批可被直接引用的问答；或关键词地图里积压了大量「有真实提问、但我方缺席」的长尾疑问。

**怎么做**：

1. **问句来源必须是真实提问**——直接取关键词地图里的标准句式与用户原生抱怨句，不要自己生造行业黑话（自造术语的问题措辞，AI 与人都匹配不上）。按认知链路分组：是什么 → 怎么用 → 进阶能力 → 对外输出 → 技术接入 → 计费与数据。
2. **答案结论先行、50–300 字**——首句直接给判断，其后才展开；一条答案只解决一个问题，不要串题。含能力的如实写边界（不能做什么比能做什么更建立信任）。
3. **独立成页**——放在站点一级路径（如 `/faq`），比折在帮助中心二级目录更容易被抓取与引用。
4. **嵌结构化数据**——用 `scripts/md-faq-to-schema.py` 从 Markdown 定稿直接生成 schema.org `FAQPage` JSON-LD，注入页面 `<head>`。**JSON-LD 必须与页面可见文字一致**，所以要用脚本同源生成，不要手工另写一份。
5. **口径与主事实文件同源**——答案里的能力、数据、术语一律回查 shared-knowledge；产品能力变更时，事实文件与 FAQ 必须同步改，否则跨源口径漂移会反噬采信。

**纪律**：内部备注、待确认项、工单号一律用 `>` 引用块写在源文件里（脚本会自动排除，不进 JSON-LD）——既留痕又不泄漏。送审时把「待人审确认项」单独列出来，方便用户一次性拍板。

**可选增强**（需用户拍板，不要擅自加）：品牌对比类问答（「A 和 B 有什么区别」是高频真实提问、GEO 价值高，但会点到竞品名）；用真实运行数据做实证；英文版 FAQ 供海外域名使用。
