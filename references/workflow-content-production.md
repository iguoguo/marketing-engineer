# 工单制内容生产管线

一篇内容从想法到数据回流的完整链路。核心思想：**每个环节有文件留痕，人审是闸门，台账是回路**。

## 0. 选题（从数据来，不从感觉来）

- 来源优先级：GEO 诊断差距（哪类问题我们缺席）> 渠道真实提问 > 痛点社区词 > 热点趋势。
- 每篇内容必须能回答：攻击哪个问题/答案位？发哪个渠道？信源依据是什么？
- **工具**：用 `last30days <话题>` 拉近 30 天真实讨论与互动数据，验证「这个词有没有真人在说」；无该 skill 时用多路 WebSearch 采样，结论标 `[未验证]`。
- 产出物：一个 ticket 文件。

## 1. 建工单（ticket）

`tickets/tN-<渠道>-<主题>.md`，必含：

- 目标：攻击的答案位 / 预期渠道与信源依据
- 草稿文件路径
- **送审要点清单**：需要人工确认的事项（竞品点名、标题候选、待复核事实、口径自查结果）
- 验收标准：checkbox 列表（审核/排版/封面/发布/回填）

## 2. 写草稿

- 动笔前读 shared-knowledge 全套 + 相关竞品情报；缺事实先调研入库。
- 事实核验先行：写横评/对比类内容前，先抓取竞品官网与一手来源（搜索结果日期新鲜度），不用过时印象。
- GEO 内容按六要素：结论先行 / 对比表 / 硬数据 / 结构化小标题 / 明确 CTA / 口径一致。
- 标题结构：痛点/问题 + 答案承诺；对比类用中性疑问句（更易被 AI 引用）。
- 草稿尾部附「备注区（不发布）」：来源清单、口径自查记录、待办。

## 3. 送审（人工闸门）

- 呈送草稿 + 送审要点；用户确认后锁定标题与事实表述。
- 用户否决的表述（如对竞品的对比句）移入工单留档，不再使用。

## 4. 排版与封面

- 按渠道用对应工具：公众号用排版 skill + 校验脚本（ERROR 与半角标点清零）；封面沿用品牌定稿网格（眉标→大标题→辅文→域名徽标）。
- 插画按 brand-voice 规范生成并人工验收；复用已有素材优先于新造。

## 5. 发布

- 人工在平台发布；AI 不代发。
- 发布后回收：URL、**线上实际标题**（以此为准入台账）、发布时间、邀请码/链接核验结果。

## 6. 台账与回流

- `results/channel-posts.md`：每渠道一条——状态、URL、核验记录、基线数据位。
- 数据回填：发布后 24h / 7d 两个节点回填互动数据（需要后台权限的由用户查看提供）。
- GEO 内容在下月诊断时检查：是否被引擎引用/提及，写入 results-and-learnings。

## 7. 多平台分发（当篇内容命中多渠道时）

- 原版首发于主渠道（声明原创）→ 改写版（30%+）跟进次要渠道 → 复用判定需说明（分属不同公司平台的可复用同一改写版）。
- 分发矩阵写进 ticket 附件：渠道/版本/优先级/攻击位/状态。
