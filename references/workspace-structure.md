# 工作区结构与渠道矩阵

## 目录模板

```
<workspace>/
├── README.md                      # 工作区宪法：先读后写、产出归位、铁律清单
├── shared-knowledge/              # 公司级事实，唯一可引用来源（无此处依据不得对外写）
│   ├── README.md                  # 文件索引表（文件/说明/状态与来源）
│   ├── product-and-offer.md       # 产品事实：定位、模块、官方话术、Offer、内部数据
│   ├── positioning.md             # 定位与差异化；含「待验证假设 [未验证]」区
│   ├── brand-voice.md             # 语音/术语表（统一说法 vs 禁用说法）/视觉规范/审核自查清单
│   ├── audience.md                # 受众画像
│   ├── channels.md                # 自有渠道清单：渠道/类型/定位/受众/域名口径/状态
│   └── toolchain.md               # 外部增强 skill 工具链：来源/许可/审计结论/接入点
├── content/                       # 垂直域：内容营销
├── geo-seo/                       # 垂直域：SEO/GEO
│   ├── knowledge/                 #   engine-question-set.md、keyword-map-<年-月>.md、ai-engine-source-map.md
│   ├── workflows/                 #   geo-content-production.md
│   ├── plans/                     #   行动方案（NOW/NEAR/FAR 三阶段）
│   └── results-and-learnings/     #   月度诊断、探针实测记录
├── outbound/                      # 垂直域：外联/分发
├── competitor-intel/research/     # 竞品情报（记录带来源+日期）
├── launch-campaigns/<campaign>/   # 活动：brief.md + tickets/ + outputs/ + results/
└── raw/                           # 原始生成素材归档
```

## 各核心文件骨架要点

- **product-and-offer.md**：一句话定位（官方口径）、价值要素、模块表、三层叙事、官方原话术（可直接引用）、内部运行数据（标注检索日期）、Offer 与「不进素材」约束。
- **brand-voice.md**：术语表三列（概念/统一说法/禁用说法）；视觉规范分场景（如公众号一套、PPT 一套）；域名双版本口径（如国内/海外两套域名，强制不得混用）；免费表述口径；发布前自查清单。
- **channels.md**：每渠道一行——类型/内容定位/核心受众/域名口径/粉丝数据 `[未验证]`；按下述分组写打法。
- **engine-question-set.md**：固定诊断问题集（品牌词/品类词/场景词/痛点词类），发现新高频提问即追加并注明来源日期。
- **toolchain.md**：登记已安装的外部增强 skill——来源、许可、安全审计结论（P0/P1/P2）、工作流接入点、调用纪律。安装任何第三方 skill 前必须审计并在此登记。

## 渠道矩阵与分发原则

1. **按受众分组，不按平台罗列**：设计人群 / AI 技术人群 / B 端职场 / 泛流量搜索 / 海外——每组指定主叙事与主力渠道。
2. **域名与语言口径随渠道走**：国内渠道与海外渠道使用各自的域名/语言版本，写入 channels.md 强制执行。
3. **分发必须改写**：一稿多投需改写 30%+（换开头、重组结构、重写表述），但**核心事实与口径严格一致**——平台有重复判定，AI 引擎有跨源一致性加分，二者要同时满足。
4. **渠道与内容匹配**：技术社区发技术文、职场社区发 B 端叙事、答题平台（知乎）以回答为主而非文章；不契合的内容宁可不发。
5. **软性参与规则**（Reddit/X 等社区）：先以真实使用者身份参与养账号，不发硬广。

## 目录语义册（驾驶舱左栏显示的一句话含义）

新增目录时同步维护，写到工作区根目录 `workspace-folders.json`（`{"路径": ["中文名","角色","一句话说明"]}`）即可覆盖内置词典。内置通用含义如下：

| 目录 | 一句话含义 |
|---|---|
| `shared-knowledge/` | 唯一可引用来源：改这里 = 改全局 |
| `content/` | 稿件大本营：`packs/` 按周放稿，`outputs/` 放成品源稿 |
| `content/packs/week-YYYY-MM-DD/` | 该周各渠道稿件与配图 |
| `geo-seo/` | 关键词地图、方法论、源稿与效果复盘 |
| `competitor-intel/` | 对标名单、对比矩阵、调研报告（对外点名需审批） |
| `launch-campaigns/<campaign>/` | brief + tickets（工单）+ outputs（产出）+ results（台账） |
| `outbound/` | 外联名单与话术 |
| `strategy/` | 结构性方案（品牌落地、营销总案、竞品方案），不直接对外 |
| `scripts/` | 构建脚本：扫描 / 构建驾驶舱 / 本地服务 |
| `raw/` | 未处理的抓取件与中间产物 |
| `assets/` | 配图、封面等素材 |
| `.workbuddy/` | AI 记忆与自动化记录（项目数据，勿删） |

子目录通用命名（未登记时按此自动生成，避免出现「尚未登记」套话）：`outputs`=成品产出、`plans`=计划、`workflows`=流程 SOP、`knowledge`=该域主题知识、`results`=结果、`results-and-learnings`=效果数据与复盘、`tickets`=工单、`screenshots`=截图证据、`distribution`=分发物料、`covers`=封面、`automations`=自动化执行记录。

## 文件状态口径（驾驶舱右栏）

| 状态 | 含义 | 判定来源 |
|---|---|---|
| 已发布 | 台账有 URL 与发布时间 | 台账命中（限 `outputs/`） |
| 待审核 / 全文已备 / 需出稿 / 草稿 | 稿件生命周期 | 文件头 `> 状态：…` |
| 定稿口径 / 方案 / 情报 / 源稿 / 内部 | 内部文档分级 | 目录规则兜底 |
| 构建物 / 素材 / 记忆 | 非内容 | 目录或扩展名兜底 |

在文件头写一行 `> 状态：待审核` 就会被自动识别；想强制指定就写进 `workspace-registry.json`（优先级最高）。

## 工作区记忆与续作

- 每日工作日志（append-only）记录决策、定稿口径、待办；长期规范沉淀到工作区记忆文件。
- 定稿内容即时写入工单/台账文件，避免只存在于对话中；台账一律以线上实际发布版本为准（用户常在发布时自行改标题）。
