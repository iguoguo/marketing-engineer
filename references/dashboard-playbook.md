# Dashboard Playbook —— 驾驶舱看板 + 排期日历 + 苹果日历同步

用户说「我需要随时查看整体的营销情况、排期、工作任务」「给我一个直观的可以看的东西」时，按本剧本交付一个**单文件静态看板**（`dashboard.html`，放工作区根目录），并把近期日程同步到系统日历。已在本工作区（2ryun-marketing）完整落地并验证。

## 一、看板设计模式（单文件 dashboard.html）

**形态**：纯 HTML+CSS+原生 JS 单文件，双击即开，无依赖、无服务器、可打印（Cmd+P 导出 PDF 汇报版）。Notion 风浅色主题（白底 / #F7F7F5 面板 / 单一强调色）。

**推荐区块**（按信息优先级排序）：

| 区块 | 内容 | 关键实现 |
|---|---|---|
| 排期日历 | 月历网格，日程色点 | 见第三节 |
| 今天看什么 | 关键节点**实时倒计时** + 6 张 KPI 卡 | 倒计时按打开日期 JS 实时计算，永不过期 |
| 排期 | NOW/NEAR/FAR 三阶段时间轴 + 机制化节奏 + 口径铁律 | 状态用 pill 标签 |
| 工单看板 | 一内容一工单，状态一目了然 | 与 `tickets/` 同步 |
| 发布台账 | 真实链接、发布时间、核验状态 | 与 `results/channel-posts.md` 同步；异常条目标红 |
| 渠道矩阵 | 全渠道分组，绿点=已发 | 与 `channels.md` 同步 |
| 待决策 | 需用户拍板的事项，卡发布的标橙置顶 | 决策落地即删除该条 |
| 竞品情报 | 周报关键动态 + 威胁等级 | 与 `competitor-intel/research/` 同步 |

**维护纪律（与用户的约定，写入工作区 README）**：
- 倒计时不用管——每次打开自动重算
- 数据变化（发布、关单、新日程、决策落定）→ agent 直接改对应区块，并更新右上角「数据截止」时间戳
- 用户在任何会话说「看下整体情况」→ 打开并先同步再看
- 首次交付前必须浏览器验收：关键区块存在、JS 无报错、分段截图检查视觉

## 二、月历实现要点（看板最前区块）

- **周一为首列**（中文习惯），固定 42 格（6 行×7 列），上下月日期灰显
- **定期节奏代码化，不逐条硬编码**：渲染器按规则生成——如 `getDay()===1` → 每周一「竞品周报」；`d===1` → 每月 1 日「月度探针」。切月自动铺入，永不漏
- **一次性日程放 `ONEOFF` 常量**：`{'YYYY-MM-DD': [[标题, 类型], ...]}`，类型即色点语义（auto=自动跑 / user=需用户动手 / done=已收口 / ms=阶段节点）
- 今日高亮（圆形强调色底）；「回到本月」按钮；今日格淡色底
- 新日程定稿 → 同步改 ONEOFF（见第四节联动）

## 三、苹果日历同步（macOS）

**两条路径，按序尝试：**

1. **首选 AppleScript 直写**（免确认、可幂等）：`osascript` 建专用日历（如「2Ryun 营销」），逐条 `make new event`。要点：
   - 日期构造用 `set day of d to 1` → 设 year/month → 再设 day，避免月末溢出
   - 写入前按 `summary` 查重（`count of (every event of c whose summary is X) is 0`），可安全重跑
   - 重复日程用 `recurrence:"FREQ=WEEKLY;INTERVAL=1"` 等 RRULE
2. **被权限拦截（报错 -10004「权限违例」即 TCC 自动化授权未放行）→ 降级 `.ics` 文件**：
   - 生成 `<产品>-<名称>日程.ics`（VCALENDAR，含 VEVENT + RRULE + **VALARM 提醒**），工作区根目录
   - `open <file>.ics` 唤起日历 App，用户点一次「好」即整批导入
   - 沙箱内 `open` 可能被拦，用非沙箱执行；AppleScript 直写同理

**事件内容规范**：description 写清「做什么 + 数据落在哪个文件 + 对照基线」，让日历提醒本身就是执行指引；每条带提前 10–30 分钟 VALARM。

**进历标准**：只进有确定日期的事。NEAR/FAR 未定稿批次不进，在看板日历 legend 里注明「日期定稿后补入」。

## 四、三处联动（新日程定稿时必须全做）

1. dashboard 月历 `ONEOFF` 加条目
2. 重新生成 `.ics`（若已有同步文件）并提醒用户重新导入
3. 工作区每日日志记一笔

同理，台账/工单/决策状态变化时 → dashboard 对应区块 + 「数据截止」时间戳一并更新。**看板是视图不是源**：源永远是 `results/`、`tickets/`、`channels.md`、周报等文件，看板从它们派生。

## 五、驾驶舱引擎：工作区全景（脚本三件套）

用户说「我想从驾驶舱看到整个工作区有哪些文件夹、每个文件什么状态、什么时候发的」时，交付「工作区全景」视图。已在 2ryun-marketing 完整落地并验证（293 文件 / 74 目录）。

### 5.1 三件套

| 脚本 | 作用 | 用法 |
|---|---|---|
| `scripts/scan_workspace.py` | 扫描工作区 → `.cache/workspace_map.json`（目录一句话含义 + 每文件日期/状态/说明） | `python3 scripts/scan_workspace.py .` |
| `scripts/build_dashboard.py` | 扫描 + 注入骨架 → 生成单文件 `dashboard.html`（含离线文本快照） | `python3 scripts/build_dashboard.py . [--force] [--title 产品名]` |
| `scripts/serve_dashboard.py` | 本地 HTTP 服务 + `/api/tree`（实时扫描）+ `/api/file`（读全文） | `python3 scripts/serve_dashboard.py . 8799` |

新工作区用 `init_workspace.py --with-dashboard` 一次性装好。

### 5.2 布局语义（不要改歪）

> **左边选目录，右边看文件。目录的说明只在左边出现一次，右边不重复。**

- **左栏（340px，sticky 自滚）**：完整层级树（含中间层），每个节点 = 目录名 + 文件数徽标（**含子目录总数**）+ 一行灰色小字说明；顶上有展开/收起/搜目录（命中即自动展开并高亮祖先链）
- **右栏**：一行面包屑（点任一段跳回上级）+ 搜索 + 状态下拉 + 文件表；**操作列固定在最右侧**（查看 / 线上↗），不要塞在标题下面
- 两个易错点：① 整段若注入在 `.wrap` 之外会左右 100% 卡边 → 给该 section 加 `max-width:1220px;margin:0 auto`；② 目录说明要**一句话**（≤20 字），长的塞进 tooltip 或详情页

### 5.3 状态判定（四级优先级）

1. **人工注册表** `workspace-registry.json` —— 最权威，内容库显示什么这里就显示什么
2. **发布台账命中** —— `**/results/channel-posts.md` 里的 URL 出现在 `outputs/` 下某文件中 → 已发布（带渠道+发布时间）。**必须排除台账自身、README、含链接的计划文件**（否则计划文件会被误判成已发布）
3. **文件头标记** —— 前 12 行内 `> 状态：待审核 / 全文已备 / 需出稿 / 草稿 / 已发布`
4. **目录兜底** —— shared-knowledge→定稿口径、strategy→方案、competitor-intel→情报、outputs→源稿、.workbuddy→记忆、scripts→构建物、图片→素材 …

状态集：已发布 / 待审核 / 全文已备 / 需出稿 / 草稿 / 定稿口径 / 方案 / 情报 / 源稿 / 内部 / 构建物 / 素材 / 记忆。顶部 chip 一点即筛、**必须有选中态**（蓝边蓝底 + ✓，hover 显示 ×，再点取消）。

### 5.4 目录含义册

- 内置通用词典（`shared-knowledge / content / geo-seo / outputs / tickets / assets / raw / …`），未登记的目录按末段名套通用词典，**禁止出现「尚未登记说明」这类套话**
- 项目定制：根目录放 `workspace-folders.json`（`{"目录相对路径": ["中文名","角色","一句话说明"]}`），扫描时自动覆盖
- 目录计数**逐级向上累加**，保证中间层（如 `content/packs`）也进树且数量含子目录

### 5.5 文件查看弹窗

- **所有文件都可点开**：Markdown 渲染（标题 / 列表 / 引用 / 表格 / 代码块 / 链接）、图片直接预览（+新窗口开原图）、二进制给路径提示
- 代码块：**灰色底**（明亮模式不要黑底）+ 右上角「复制」按钮；按钮挂在外层 `.codewrap` 上而不是 `pre` 内，避免横向滚动时按钮漂移；**别动 ProseMirror 内部的 pre**（会破坏编辑器 DOM）
- 文档头部 `> 状态：… / > 日期：…` 这类元信息，渲染成**元信息卡**（键左值右、浅灰底、无蓝条），不要当普通引用块
- 正文铺满弹窗宽度（`.doc{max-width:none}`，弹窗宽 ~1240px，左右留白一致）

### 5.6 主题（明亮 / 暗夜）

- 切换按钮挂进**常驻的 nav**（sticky，滚动时也可见）；选择存 `localStorage`，默认跟随系统 `prefers-color-scheme`
- 用 CSS 变量分层：`--bg/--panel/--panel2/--line/--text/--muted/--dim/--accent*` + `--surface/--surface2/--hover/--codebg/--codetext`
- **铁律：所有 hover 态必须走 `--hover` 变量**。硬编码 hover 底色是暗色模式第一大坑（典型案例：`tbody tr:hover{background:#FAFAF8}` 在暗色下变白底 + 浅灰字，完全看不清）
- 暗色下另需覆盖：nav 半透明底、`.tabbtn.active`、`.mbtn.primary`、toast、遮罩、图片亮度

### 5.7 更新机制（两种都要提供）

1. **实时**：起 `serve_dashboard.py`，页面 fetch `/api/tree` → 页头显示「● 实时扫描」；**每次打开重新扫描**
2. **手动**：内容变化后跑 `build_dashboard.py`（幂等，旧文件自动备份到 `.cache/`）

浏览器不能自己读本地磁盘目录，所以「自动刷新」只能靠服务；离线时回退内嵌快照，也要能用。

### 5.8 扩展机制

- 任何 `<section id="tab-xxx">` 自动成为一个 Tab（无需改 JS）；自定义区块用 `<!-- CUSTOM:START/END -->` 包起来，重建时自动迁移
- 想让驾驶舱显示别的内容（KPI、月历、台账…），直接手写 section，数据源仍是工作区里的 md 文件

### 5.9 踩坑清单

1. 后台服务**常驻会用旧模块代码** → 改完扫描脚本必须重启服务
2. 后台服务用 `&` 起会随命令结束被回收 → 用后台任务方式启动
3. 根文件容易重复计数 → 逐级取真祖先累加，别在循环里对根多加一次
4. 目录说明里写 HTML 标签（`<b>`）会被转义成字面量 → 说明文本用纯文本
5. 批量替换 `#fff` 时只换 `background:` 前缀，`color:#fff` 要保留并在暗色下单独覆盖
6. 内嵌文本快照会让 HTML 变大（几 MB 级）→ 设预算（默认 1.2MB / 每文件 4000 字符），并跳过 `dashboard.html` 自身
7. 台账 URL 匹配要限定目录 + 排除说明类文件，否则误判一片「已发布」
